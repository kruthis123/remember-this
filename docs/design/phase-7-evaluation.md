# Phase 7 — Evaluation

Status: decided. Decision record: `decisions/ADR-008-evaluation.md`.

Built **before** the bot works end to end (ADR-001).

## Dataset

Everything LLM-generated, human-reviewed. Two parts:

**Distractor corpus** — a few hundred unrelated memories per simulated user. Purely filler; its job is to
make retrieval hard. No ground truth attached. Generated wholesale.

**Labelled cases** — roughly 40–60 cases carrying ground truth. Each case has:

| Field | Purpose |
|---|---|
| stored message(s) | the input, including deliberately messy multi-fact ones |
| expected facts | what extraction should produce — grades the write path |
| question | paraphrase-varied, sometimes indirect |
| expected memory id(s) | grades retrieval independently of answering |
| reference answer | grades answering, judged semantically |
| expected abstention | true for cases where nothing relevant was stored |

Ground truth is **both** reference answer and expected ids, so retrieval and generation are separable. When
end-to-end fails, the ids tell you which half broke.

Case categories to cover deliberately:

- clean single-fact store and recall
- messy multi-fact store, each fact recalled separately
- exact identifiers and proper nouns (verbatim fidelity)
- indirect phrasing ("that Mexican place" for a named restaurant)
- near-duplicate distractors — several memories on the same topic, one correct
- true absence — nothing stored, abstention is the right answer
- borderline relevance — a memory is topically close but does not answer the question

**Excluded:** latest-value/contradiction cases. They are a declared non-goal (ADR-003) and including them
would fail the release gate on a limitation chosen on purpose. Stated here so the exclusion is visible rather
than convenient.

## Generation risks to review for

Human review exists to catch three specific failure modes in generated data:

1. **Lexical leakage** — generated questions that reuse the fact's wording, making retrieval trivially easy
   and the metrics flattering. Questions must be paraphrased away from the stored text.
2. **Same-model bias** — cases generated by the model under test will favour what that model finds easy. The
   generator should be a different model from the system model, and different again from the judge.
3. **Ambiguous ground truth** — cases where two answers are defensible. These poison every metric and are
   only catchable by a human reading them.

Review is not a rubber stamp; it is the step that decides whether the numbers mean anything.

## Metric suites

| Suite | What it measures | Method |
|---|---|---|
| extraction | did extraction capture every fact, without distortion or over-splitting | LLM judge against raw message |
| retrieval | were the expected memory ids returned above threshold | deterministic: recall, hit rate |
| relevance check | did it correctly accept/reject weak candidates | deterministic against labels on borderline cases |
| faithfulness | does the answer assert anything absent from retrieved facts | LLM judge |
| correctness | does the answer match the reference, allowing paraphrase | LLM judge |
| verbatim fidelity | identifiers and proper nouns reproduced exactly, case included | deterministic string assertion |
| abstention | appropriate refusal, and appropriate non-refusal | deterministic against `expected abstention` |
| attribution | cited memory id is the one actually used and supports the answer | deterministic id check |
| routing | tool chosen matches intended intent | deterministic |

Read as pairs, never as a single score: **faithfulness with false-abstention rate**, and **retrieval recall
with abstention rate**. Either half of each pair is trivially gamed at the other's expense.

## Judges

- Judge model differs from the system model (ADR-005) — self-preference bias is well documented.
- Generator model differs from both, where the available models allow it.
- Each judge gets a written rubric with a small discrete scale. No continuous 1–10 scores; they invite
  false precision and inconsistency.
- Judges receive the retrieved facts, the question, the answer, and the reference. Nothing else.

### Judge validation

50 cases hand-labelled by you, compared against judge verdicts. Report raw agreement and a chance-corrected
statistic (Cohen's kappa). Poor agreement means the rubric is revised and the judge re-run, not that the
labels are adjusted.

This step is the difference between using judges and trusting them. An unvalidated judge produces numbers
with no known relationship to reality, and skipping it is the most common gap in projects that look like this
one — which makes doing it a differentiator worth writing up.

## Harness and execution

**Langfuse-native.** Datasets, experiments, and scores live in Langfuse; runs are triggered locally. Less
code, and comparison across runs comes free. Cost: scores consume Hobby quota (ADR-007), so a full sweep over
~50 cases and nine suites is quota-relevant — worth measuring the cost of one run early.

**Local execution only.** No CI. The gate is procedural, not automated: no prompt, threshold, or model change
ships without a run.

Honest weakness: a procedural gate depends on remembering. Worth mitigating with a pre-deploy checklist in
the README, or a hook that refuses a deploy without a recent run.

## Gating

**No-regression against a recorded baseline**, not absolute thresholds. The first full run establishes the
baseline; later runs must not degrade the gated metrics.

Gated: faithfulness (fabrication), false-abstention rate. Reported but not gated: latency, tokens, retrieval
recall, extraction quality.

With ~50 cases, one case flipping is a two-percentage-point swing, so small movements are noise. Either
tolerate a band or read metric changes alongside the individual cases that moved — the latter is more
informative at this size and cheap when the dataset is this small.

## Dataset growth

Thumbs-down in production (ADR-007) → review the trace → add the case with corrected ground truth → it becomes
a permanent regression guard. This is the loop worth demonstrating: a real failure, a trace, a fix, and a test
that prevents its return.

Since Langfuse retention is about a month, cases must be pulled into the dataset promptly rather than left in
traces.
